# 005 — Dynamic Skill Resolution + Scale Adaptation

**XXX:** 005-dynamic-skill-resolution-scale-adaptation  
**Field:** Foundation  
**Status:** OBSERVED  
**Scope:** Universal Toolkit only

## Baseline

Slice 004 froze the Responsibility Unit and Seat model. Its strongest invariant is that Agent count changes allocation, not the underlying skill library, authority, or authorization.

## Finding

A reusable resolver can make skill selection deterministic when it consumes the already-defined project, field, phase, task, provider/runtime, tools/plugins, guidance, permissions/policy, and capacity context. The resolver must remain instructional and must not manufacture authorization.

## Validation target

The same context at 2, 4, and 8 Agents must resolve the same skill identifiers and authority boundary. Only the allocation profile may differ.

## Governance discovery during 005

The first 005 branch execution caused an unintended rewrite of `MASTERPLAN.md`, deleting canonical sections while updating the active frontier. The existing canonical-integrity gate correctly blocked that change by detecting removed headings and a large deletion. The repair rule is therefore explicit: restore the lost canonical structure and apply only the authorized 005 frontier changes.

This incident also establishes a future 007 requirement. The long-term validator must protect **knowledge lineage**, not freeze document shape forever. A legitimate future migration or retirement of canonical structure must declare its authorized scope, successor/target or retirement reason, and evidence. An unexplained disappearance remains fail-closed.

## Boundary

No consumer-specific Product Law, credentials, provider decision, autonomous authorization, or runtime scheduler is introduced by this slice.
