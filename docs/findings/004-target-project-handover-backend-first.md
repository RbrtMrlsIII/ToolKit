## Generalized lesson
A reusable agent toolkit must separate process ownership from consuming-project ownership.

- After a new product idea is established, backend authority should be clarified before implementation can silently become UI-first.
- A consuming project owns its own architecture, contracts, evidence, checkpoints, and handover.
- A completed gate in the consuming project must surrender a target-project handover package/ZIP in the same execution.
- The reusable toolkit supplies the rule/skill only; it must not become the handover owner or export project-specific state as though it were a toolkit artifact.
- A parked/blocked gate may carry a pause record, but that record must not be represented as a completed-gate handover.

## Why it matters
Without this separation, agents can preserve planning discipline while still losing the actual target-project state needed for continuation, or can accidentally make the toolkit a second authority over the consuming project.
