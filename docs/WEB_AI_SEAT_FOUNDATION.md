# WebAi Seat Foundation

This document defines the reusable foundation for WebAi seats. A seat is a responsibility boundary assembled from reusable skills, workspace governance, project adaptation, and current execution capacity.

## Responsibility Unit

```text
objective
+ scope
+ required knowledge
+ required skills
+ authority boundary
+ inputs
+ dependencies
+ outputs
+ verification
+ handover
```

## Seat

```text
Seat
= responsibility units
+ workspace governance
+ project adaptation
+ skill bundle
+ execution capacity
```

A seat may carry multiple responsibility units. The bundle is dynamically resolved to the smallest sufficient set rather than copied per Agent.

## Agent allocation

```text
Agent
= currently assigned responsibility units
```

With two Agents, several compatible units may be grouped. With up to eight Agents, units may be split into narrower assignments. Scaling changes allocation and coordination, not authority or the underlying universal skill definitions.

## Skill relationship

Skills instruct HOW work is performed. Policy, permissions, workspace and project authority determine WHETHER an Agent may act. Product Law determines WHAT is true.

## Adaptation

The effective seat bundle is selected from project type, field, phase, current slice, task/domain, provider/runtime, tools, project guidance, permissions, and available Agent capacity.

## Growth

Every validated execution baseline triggers a skill-coverage review. Existing skills should be reused where sufficient. New reusable procedures become candidate skills or extensions only after validation and explicit endorsement. Consumer-specific knowledge remains downstream.
