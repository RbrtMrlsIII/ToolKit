# WebAi Seat Foundation

## Purpose

Universal AGENT ToolKit is the reusable operating foundation from which WebAi seats can be equipped. It is not a TeamAi-specific product implementation and it is not merely a collection of skills.

## Seat equipment

ToolKit supplies reusable:

- skills and skill-resolution rules;
- workspace governance, continuity, validation, reconciliation, and knowledge discipline;
- project/field adaptation and scale adaptation;
- rules for distinguishing reusable lessons from project-specific knowledge.

A seat is a responsibility boundary that loads the smallest sufficient skill bundle for its current project, phase, task, and available execution capacity. Skills instruct; project policy and permissions authorize.

## Two-axis growth

ToolKit grows in two dimensions:

1. **Technical growth:** reusable skills, adapters, tools, and supported project/field types.
2. **Operational growth:** stronger governance, continuity, evidence discipline, anti-pattern detection, responsibility allocation, and adaptation to project size and Agent count.

The goal is disciplined capability, not capability growth alone.

## Consuming-project boundary

Consuming projects retain authority over their own Product Law, domain rules, provider choices, implementation details, credentials, authorization, and user-facing product semantics. ToolKit knowledge never changes a consuming project automatically.

## Upstream learning loop

```text
ToolKit
  → reusable process/skill
  → consuming project / WebAi seat
  → real execution + evidence
  → validated finding
  → generalized lesson
  → ToolKit
```

Only validated and generalized lessons move upstream. Non-reusable knowledge remains in the consuming project.

## Agent-count scaling

Agent count is a resource-allocation variable, not a reason to duplicate the skill system. The same responsibility units and skill definitions should remain composable when a project runs with fewer Agents and splittable when more Agents become available.

A two-Agent project may combine several responsibility units per Agent; a larger project may distribute those same units across more Agents without changing the underlying universal skill definitions.
